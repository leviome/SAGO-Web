# SAM2 Large 跨视角 memory 与下载确认

当前版本在浏览器中运行同一份 SAGO `sam2_hiera_large.pt` 的图像编码、提示解码、memory encoder 和 memory fusion。保留 FP32，使用 ONNX Runtime Web 1.23.2 / WebGPU；不需要 Python 推理服务。

## 使用流程

1. 打开场景，选中一个可见图层，调整视角后进入 **SAGO · 智能分割**。
2. 点击 **加载模型并编码画面**。若缺少模型文件，会先弹框显示总大小、已缓存大小和本次下载量。点击 **下载模型** 后显示进度条、百分比、已下载字节和当前文件；可取消。
3. 点选或框选目标，预览并选择合适的 level，然后点击 **以当前结果建立 / 重建记忆**。
4. 可先应用三维选区，再返回场景小幅旋转视角。
5. 再次打开分割工具，加载并编码新画面，点击 **用记忆跟踪此视角**。无需重新打点。
6. 检查预览。目标正确时点击 **确认并更新此视角记忆**，再按需应用三维选区或取交集。仅预览、重复预览或取消不会更新历史。
7. 若目标丢失，不写入记忆，也不允许将该跟踪结果应用为选区。补点或框选后重新建立记忆。点击 **清除对象记忆** 可开始另一个对象。

记忆保留在当前页面会话中，刷新页面后清除。绑定当前图层；切换或删除该图层、执行外部编辑会清除记忆。工具自身提交选区不会清除已确认记忆。

## 范围与历史管理

- 单个对象、一份初始提示记忆，外加最近 **6** 个确认视角的 memory 和最近 **15** 个对象指针；较旧数据自动淘汰，内存不会随视角数量无限增长。
- 手动补点产生的新结果可以重建初始记忆，并清空旧历史。
- 初始提示分割沿用 level 0 默认值，可手选其他候选；无提示跟踪按原版规则在 level 1–3 中选择最高模型评分，仍可查看其他候选。
- 初始记忆使用二值化 mask 编码，跟踪记忆使用 sigmoid mask 编码；均使用所选候选对应的 logits 和对象指针。
- 固定初始记忆位置索引 6；近期记忆按最近优先，使用位置索引 0–5。SAM2.0 的对象指针位置编码为零。
- 大幅跳转视角、严重遮挡或目标离开画面仍可能跟丢。建议连续小幅旋转并检查预览，防止错误结果进入历史。

自动巡航现已接入：在预览初始 mask 后点击 **Virtual Drone · 自动多视角细化并应用**。自动双向跟踪、自验证和三维候选收紧的细节见 [VIRTUAL-DRONE.md](VIRTUAL-DRONE.md)。手动 memory 功能仍可独立使用；动态 TAG 尚未移植。

## 下载和缓存

完整模型静态资产约 **957 MB（913 MiB）**，包含图像模型与 memory 模块。旧版已缓存的相同哈希文件可以复用；更新后的解码器和新增 memory 文件会重新询问下载。弹框以当前实际缺失量为准。

确认前只请求小型模型清单，不请求权重。下载使用最多 **4 路并发**，16 MiB 及以上的文件按 **8 MiB** HTTP Range 分块，临时网络失败最多重试两次。进度显示已下载字节、速度、预计剩余时间和当前并发数。服务器不支持 Range 时回退为完整文件下载。

Cache API 保留已完成的块，取消 / 刷新后只重新下载缺失块；未完成块重新下载。完整文件组装后校验 SHA-256，通过后才用于模型推理，随后以完整文件替代分块缓存。缓存不可用或空间不足时仍可推理，但不能保证续传或下次复用。

**跨域名复用**：浏览器缓存与 IndexedDB 按来源隔离，新域名不能自动读取旧域名的数据。点击 **选择本机模型文件夹（跨域名复用）**，再加载模型，会将校验后的文件保存到所选目录下的 `sago-sam2-large-fp32/`。已在浏览器缓存中的文件直接复制，无需重复下载。以后更换域名，在桌面 Chrome / Edge 中重新选择同一模型目录并授权即可。目录中的文件会校验 SHA-256，缺失或损坏部分才询问下载；刷新页面后如需从本机目录读取，也需重新选择目录。文件本身长期保留，不依赖网页缓存。

本机目录保存的是浏览器使用的原版 FP32 ONNX 图、权重分片和 `manifest.json`，不是 PyTorch `.pt` 文件。目录是普通本机文件，可复制到另一台机器继续使用；不会因为清理网页缓存而丢失。跨域名时的重新选择 / 授权是浏览器要求，不能由网页绕过。

运行时初始化和 GPU 着色器编译不是网络下载，显示为独立状态。若在初始化期间取消，当前初始化调用结束后会释放已创建的模型会话。

## 导出与重现

在含 PyTorch、OpenCV、ONNX 1.16.2 的 SAGO 开发环境中：

```bash
# 两个导出阶段必须使用同一份 checkpoint
/path/to/python scripts/export-sam2.py
/path/to/python scripts/export-sam2-memory.py
npm run build
```

也可设置 `SAGO_PYTHON` 后运行 `npm run models:export`：已有完整且哈希正确的资产会直接复用，否则重建两个阶段。

memory fusion 的复数 RoPE 改写为等价的实数 sin/cos 运算；注意力按 256 个 query 一组计算，避免超出浏览器缓冲区限制。位置编码、权重、残差和归一化沿用原版。对象指针使用动态 `Where` 保留目标存在/丢失分支，避免 ONNX 导出时固化 Python 条件。

## 验证

参考输出由原版 PyTorch/CUDA 产生，测试历史组合为 `(memory 数量, pointer 数量) = (1,1)、(3,3)、(7,16)`，涵盖首个跟踪视角、动态历史长度和容量上限。

- WebGPU 与原版 memory encoder 平均绝对误差约 `1.9×10⁻⁴`。
- memory fusion 平均绝对误差 `1.6×10⁻⁶` 至 `1.5×10⁻⁵`。
- 使用相同融合特征的跟踪解码：三种历史配置下，四个低分辨率二值掩码均一致；logits 平均误差约 `0.0024–0.0027`。
- Chrome / RTX 4090 端到端测试通过：建立记忆后旋转 8°、16°，不打点进行跟踪，确认写入，重复预览不写入，三维交集非空，清除记忆有效。
- 下载拒绝前零权重请求；实时进度可见；取消、续用已完成文件、缓存复用及损坏校验有测试覆盖。
- 下载 / 本机目录升级验证：16 项单元测试通过；真实 Chrome 中保存全部 39 个文件、删除模型 Cache API 缓存、刷新并重新选择目录后，SAM2 Large 编码成功且没有新增权重请求。另有独立浏览器文件系统测试覆盖刷新与缓存删除后的读取。

数值测试用于验证实现一致性，不是复杂真实场景下跟踪准确率的评测。参考数据来自已有场景图，历史容量测试使用构造的历史特征。

```bash
/path/to/python scripts/validate-memory.py
node scripts/validate-memory.mjs
npm run test:sago
npm run test:browser
```

详细结果在 `artifacts/memory-validation/report.json`，不发布到静态网站。界面诊断 JSON 包含当前图像、掩码及 memory 状态，不包含历史特征；不能用单图提示脚本重放 memory 跟踪结果。
